# Habit Tracker

개인의 습관, 생활, 소비, 투자, 복권 기록을 한곳에서 관리하는 Android 앱입니다. 생활 기록은 Room DB에 저장되며, 주식의 실시간 조회와 주문 기능은 한국투자증권(KIS) API 연결이 필요합니다.

## 주요 기능

### 홈

- 달력에서 날짜별 기록 상태 확인
- 선택한 날짜의 일기, 운동 내역, 기타 생활 기록 요약
- 일일 기록, 일기, 메모, 통계, 카드, 주식, 로또, 화분 관리 화면 바로가기

### 일일 기록과 항목 관리

- 날짜 및 휴일 여부를 지정하여 생활 기록 저장
- 카테고리별 기록 항목 필터링
- 숫자, 체크 여부, 텍스트, 시간, 운동 기록 유형 지원
- 걷기 거리와 운동 시간 등 운동 수치 기록
- 기록별 메모와 첨부파일 데이터 구조 지원
- 관리 화면에서 카테고리, 항목명, 단위, 유형, 표시 색상 등록 및 삭제

### 일기

- 날짜별 일기 작성 및 상세 조회
- 날씨와 사진을 함께 저장
- 저장된 일기를 날짜 기준으로 탐색

### 메모

- 일반 메모와 잠금 메모 작성
- 메모 검색 및 수정
- 잠금 메모에 4~10자리 숫자 비밀번호 설정

### 생활 통계

- 월간·연간 기간 전환
- 항목별 완료 횟수, 숫자 합계, 운동 거리와 시간 집계
- 일별 또는 월별 추이를 차트로 표시

### 카드 사용 이력

- 카드 사용일, 결제 예정 금액, 메모 등록 및 삭제
- 결제일을 기준으로 월별 결제 예정액 계산
- 최근 3개월 사용 흐름과 전년도 동일 월 비교

### 화분 관리

- 화분 정보와 사진 등록·수정·삭제
- 물주기 주기와 다음 예정일 관리
- 오늘 물주기 완료 처리 및 주기 1일 연장
- 1개월은 30일 기준으로 다음 물주기 날짜 계산

### 로또 6/45

- 홈과 하단 메뉴의 동행복권 선택 화면에서 로또 6/45·연금복권 720+로 분기
- 균형형·분산형 추천 번호 생성 및 저장
- 구입 이력, 추첨 결과, 저장 번호, 당첨 이력 관리
- 공식 등수별 1게임 당첨금을 동기화해 구매 번호의 예상 당첨금으로 표시하고, 실제 수령액은 수동 당첨 이력으로 별도 관리
- 로또·연금복권의 구입액, 당첨액, 손익 집계
- 생성 방식별 당첨 통계, 패턴 적합 점수, 무작위 대조군 비교
- 기간별 로또·연금복권 금액 흐름 확인

### 연금복권 720+

- 회차, 조, 6자리 1등 당첨번호 저장
- 당첨번호 숫자 입력 시 다음 자리로 자동 이동
- 최근 당첨번호를 최신 회차순으로 표시하고 스크롤 시 12회씩 추가 조회
- 4주, 8주, 12주, 16주, 24주, 52주 단위 분석
- 각 회차의 직전 선택 기간을 기준으로 자리별 가중 점수 계산
- 선택 기간의 최신 회차에 기간 수만큼 점수를 부여하고 과거 회차로 갈수록 1점씩 차감
- 입력한 6자리 번호와 기간 내 당첨번호의 동일 자리 일치 개수 확인
- 동일한 1등 번호가 있었는지는 선택 기간과 관계없이 전체 회차에서 확인
- 자리별 숫자 출현 통계에서 `기간횟수회(전체횟수)` 형식으로 함께 표시
- 기간 내 최다 출현 숫자는 붉은색, 최소 출현 숫자는 푸른색으로 구분
- 당첨번호 내부의 동일 숫자를 3자리 이상, 2자리, 중복 없음으로 구분하여 선택 기간과 전체 횟수 표시
- 직전 16회 데이터가 모두 있는 회차만 대상으로 16주 합계 점수 분포 계산
- 합계 점수를 50점 이하, 51~70점, 71~90점, 91~110점, 111점 이상으로 구분하여 회차 수와 비율 표시
- 별도 연금번호 생성 화면에서 출현형과 미출현 혼합형 번호 생성
- 가장 빈도가 높은 16주 점수 구간과 최근 16주·장기 통계를 혼합한 동일 숫자 유형을 필수 적용 조건으로 사용
- 미출현 혼합형은 과거 16주 0점 자리 수의 최빈값만큼 미출현 숫자를 반드시 적용하며, 최빈값이 0개이면 최저점 숫자를 1~2자리에 적용
- 마지막 자리를 가장 먼저 선점하고 자리별 통계 점수로 마지막 숫자를 선택한 후 나머지 다섯 자리를 생성
- 출현형과 미출현 혼합형을 개별 재생성하거나 사용자 확인 후 배치 단위로 DB에 저장하고 최신 추천 번호와 이전 생성 히스토리 표시
- 출현형·미출현 혼합형의 마지막 숫자를 서로 다르게 생성하고 생성 배치 삭제 지원

## 복권 번호 생성 로직 설계 원칙

이 절은 로또 6/45와 연금복권 720+ 생성 로직을 수정하거나 검토할 때 적용하는 기준이다. 현재 구현과 이 기준의 차이가 발견되면 별도 요구사항이 없는 한 이 기준에 맞춰 정리하며, 일부 생성 결과나 단기 당첨 이력만 보고 원칙을 바꾸지 않는다.

### 공통 원칙

- 복권 추첨은 무작위이며 모든 유효한 번호의 당첨 확률이 같다는 전제를 유지한다. 추천 점수나 과거 통계를 당첨 예측 또는 당첨 확률 상승으로 표현하지 않는다.
- 과거 당첨 이력은 후보의 적합도와 분산을 평가하는 보조 신호로만 사용한다. 같은 빈도·번호쌍·자리별 통계를 후보 추출과 순위 계산에 중복 적용하지 않는다.
- 번호 범위, 자릿수, 한 게임 내 중복처럼 유효성에 해당하는 조건만 필수 검증으로 두고 통계 특성은 원칙적으로 소프트 점수로 반영한다. 단, 연금복권 화면의 `적용 조건`에 표시하는 점수 구간, 최근·장기 혼합 동일 숫자 유형, 0점 자리 수와 추천 구성은 명시적인 필수 조건으로 적용한다.
- 특정 번호, 번호대, 직전 회차 중복 개수 또는 자리별 숫자가 반복적으로 선택되지 않도록 생성 결과의 빈도와 분산을 확인한다.
- 동일 배치와 저장 이력에서 새로 생성하거나 재생성한 번호의 의도하지 않은 완전 중복을 방지한다. 배치 전체를 저장하는 이력에서는 재생성하지 않은 반대 유형이 이전 배치와 같을 수 있음을 구분한다.
- 생성 당시 기준 회차, 분석 기간, 난수 시드, 설정 스냅샷 또는 설정 해시를 저장해 결과를 추적하고 재현할 수 있게 한다.
- 실제 생성 표본은 번호별·자리별 빈도, 배치 내 재사용, 완전 중복, 직전 회차 중복 분포를 무작위 대조군과 비교한다. 검증되지 않은 신호는 강제 조건이나 가중치로 승격하지 않는다.

### 로또 6/45

- 후보 조합은 1~45에서 중복 없이 균등하게 생성하고, 과거 번호·번호쌍·미출현 간격 정보는 점수 단계에서 한 번만 반영한다.
- 합계·홀짝·연속수·번호대·분산·과거 당첨 조합 일치 여부는 후보를 강제로 제외하지 않고 점수와 결과 설명에만 반영한다.
- 최근 16주 신호는 매 회차 자동 갱신하되 장기 통계와 혼합해 약하게 반영한다. 번호 빈도는 16·52·156주·전체 기간으로 나누고, 16주 신호는 사전 보정과 낮은 비중을 적용한다.
- 균형형은 한 게임의 일반적인 분포 적합도를, 분산형은 여러 게임을 함께 생성할 때의 번호 범위와 조합 다양성을 우선한다. 분산형이라는 이유로 32 이상 번호 개수 등을 모든 게임에 고정하지 않는다.
- 직전 회차 번호 0개, 1개 또는 2개가 자연스럽게 나올 수 있어야 한다. 직전 회차와 거의 같은 극단적인 조합만 낮은 소프트 패널티로 제한한다.
- 기본 5게임에서는 같은 번호의 과도한 반복과 게임 간 높은 중복을 제한하되, 특정 인기 번호를 배치 전체에서 우선 선택하지 않는다.
- 공동당첨 회피 점수는 생일 숫자나 단순 패턴 쏠림을 줄이기 위한 낮은 비중의 보조 점수로만 사용하며 당첨 가능성 점수로 취급하지 않는다.
- 사용자 노출 생성 버전은 데이터가 충분히 축적되고, 그 데이터를 근거로 생성 로직을 변경할 때만 올린다. 그 외 조정은 같은 버전 안에서 설정 스냅샷 또는 해시로 구분한다.

### 연금복권 720+

- 화면의 `적용 조건`에 표시하는 최빈 16주 점수 구간, 최근 16주 25%와 최근 156주 75%를 혼합한 최빈 동일 숫자 유형, 과거 회차에서 계산한 최빈 0점 자리 수를 생성 결과가 반드시 만족해야 한다.
- 추천 구성은 출현형 1개와 미출현 혼합형 1개를 모두 충족해야 하며 한 유형만 생성된 결과는 저장하지 않는다.
- 마지막 자리를 가장 중요한 자리로 취급한다. 출현형은 최근 16주 출현 후보 안에서 최근 16주 25%와 최근 156주 75%를 혼합한 자리별 점수로 마지막 숫자를 먼저 선택하고, 미출현 혼합형은 마지막 자리의 미출현·저점 숫자를 우선 선점한 다음 앞의 다섯 자리를 생성한다.
- 마지막 자리의 통계 점수 우선 선점은 연금복권에 명시된 예외로, 필수 점수 구간 검증과 함께 적용한다. 나머지 다섯 자리에는 같은 점수를 후보 추출 가중치로 다시 중복 적용하지 않는다.
- 출현형은 최근 16주 자리별 출현 숫자로 나머지 자리를 구성한다. 미출현 혼합형은 최빈 0점 자리 수를 정확히 적용하고, 0점 자리 수가 0개이면 최저점 숫자를 1~2자리에 적용한다.
- 두 유형은 마지막 숫자와 조를 서로 다르게 하고 최소 3자리 이상 차이를 확보한다. 한 끝자리 후보가 나머지 필수 조건을 만족하지 못하면 다른 유효 끝자리도 재탐색한다.
- 조 번호는 1~5 균등 확률 25%, 최근 16주 출현 비율 25%, 최근 156주 출현 비율 50%를 혼합한 약한 가중치로 선택한다. 중복 여부는 6자리 번호뿐 아니라 조와 번호의 조합, 공식 당첨 이력, 저장된 생성 이력을 함께 구분하며 새 추천 번호는 저장된 6자리 번호를 반복하지 않는다.
- 화면에는 현재 출현형·미출현 혼합형의 마지막 자리 후보 숫자를 표시한다. 최근 16주 분석 조건이 바뀌면 기존 생성 번호를 현재 조건의 번호로 오인하지 않도록 표시하며, 생성 당시 조건과 현재 조건을 각각 확인할 수 있게 한다.

### 복권 데이터 수집 보완 검토

2026-09-06 소스 검토 기준. 아래는 현재 저장 구조에 대한 검토와 후속 제안이며, 실제 DB의 데이터 개수·누락 여부나 생성 성능을 실행 검증한 결과가 아니다.

수집 목적은 무작위 생성에 과거의 반복 패턴과 최근 흐름을 반영하면서, 그 선택이 이후 회차에서도 유효한지 확인하는 것이다. 사용자는 확정 당첨번호가 아닌 데이터에 따라 후보의 우선순위가 이동하는 생성 방식을 원한다. 제외 조건 역시 검증할 가설이며, 단기 빈도 차이를 예측력으로 단정하지 않는다. 현재 16회·156회 혼합 비율은 초기 설정으로, 충분한 데이터가 쌓였다는 근거 자체가 아니다.

| 우선순위 | 현재 확인한 상태 | 보완 제안과 이유 |
| --- | --- | --- |
| 높음 · 연금 생성 추적 | 생성 배치·유형·조·번호·자리 점수·저장 시각은 있으나 대상 회차, 분석 마지막 회차, 시드, 설정 스냅샷·해시가 생성 엔티티에 없음 | 생성 시점의 기준 회차·설정·입력 데이터 식별값을 남겨 당시 패턴과 결과를 비교. 현재 `generatedAt`은 저장 시각에 설정되므로 실제 생성 시각도 구분 |
| 높음 · 로또 설정별 평가 | 번호별 시드·분석 기준 회차·설정 해시·피처 스냅샷과 설정 JSON 저장 구조가 있음. `LottoPerformanceAnalyzer`의 표본·집계는 방식과 생성 버전을 기준으로 함 | 기존 설정 해시를 성과 분석까지 전달해 같은 버전 내 다른 설정의 결과를 분리. 추가 크롤링보다 기존 데이터 활용 보완이 우선 |
| 높음 · 연금 평가·구매 연결 | 구매에는 회차·연금번호 문자열·금액이 있으나 생성 번호 ID와의 명시적 연결이 없음 | 생성 번호별 평가 대상 회차와 실제 구매 회차·수량을 구분. 같은 번호를 여러 주 구매할 때도 회차별로 평가하고, 미구매 추천의 가상 성과와 실제 손익을 분리 |
| 높음 · 공정한 비교 표본 | 로또에 평가 대상 표시와 대조군 비교 구조가 있음. 연금 생성 엔티티에는 대조군·평가 대상 식별 항목이 없음 | 추첨 전에 확정한 추천과 같은 회차·같은 게임 수의 무작위 대조군을 남김. 좋은 결과만 저장하거나 재생성·삭제로 실패 표본이 빠지는 편향을 방지할 평가 기록 정책을 별도 결정 |
| 높음 · 원본 품질 | 로또는 출처·원본 해시·저장 시각이 있음. 연금 추첨 엔티티는 회차·조·번호·보너스만 저장. 동기화 상태는 최근 상태 중심 | 연금에도 회차별 출처·수집 시각·원본 식별 정보 보완 검토. 연속 회차와 보너스 누락을 확인하고, 일부 회차만 있는데 `16주`로 해석하지 않도록 실제 기간·표본 수 구분 |
| 중간 · 재현 가능한 입력 | 로또의 마지막 분석 회차와 원본 해시만으로 이후 원본 수정 전 데이터를 복원할 수는 없음 | 전체 입력 데이터의 식별 해시와 정정 이력 보존 검토. 시드만으로 재현된다고 단정하지 않고 설정·입력·구현을 함께 식별 |
| 중간 · 패턴별 평가 | 로또는 피처 스냅샷, 연금은 자리 점수·중복 유형·미출현 위치 저장 구조가 있음 | 최근·장기 실제 표본 수, 선택 당시 적용 가중치·제외 사유를 추적. 로또는 일치 개수·등수, 연금은 조 일치·끝자리 연속 일치·보너스 결과를 구분해 평가 |

- 과거 회차 검증에서는 해당 회차 이후 데이터를 사용하지 않는다. 설정을 고르는 구간과 평가 구간을 나누고, 여러 패턴을 시도해 우연히 좋아진 결과를 구분한다. 게임 수뿐 아니라 독립된 추첨 회차 수와 불확실성을 함께 보고한다.
- 최근 16회와 최근 156회는 서로 겹친다. 현재 혼합 비율은 두 창의 점수 비중이며, 최근 데이터가 전체 결과에 기여하는 비율과 같다고 설명하지 않는다.
- 현재 연금복권은 점수 구간·중복 유형·미출현 구성 등의 필수 조건과 과거 당첨번호 제외를 유지한다. 로또의 통계적 소프트 점수 방식과 완전히 동일하지 않으며, 제외 효과를 검토할 때 이 차이를 남긴다.
- 공식 당첨금은 손익 평가에 유용하지만 번호 패턴의 예측력을 입증하는 데이터는 아니다. 실제 수령액을 수동으로 관리하는 사용자 정책은 유지한다. 날씨·판매점 등 생성 가설과 연결되지 않은 자료는 우선 수집 대상에 추가하지 않는다.
- 이번 검토는 문서에만 반영했다. 수집 필드·DB·생성 로직·성과 집계 변경은 별도 구현 범위로 다룬다.

## 개발 환경

### 화면 디자인 기준

- Material 3 기반의 밝은 중립 배경과 청록 포인트를 사용한다. 제목·본문·보조 정보의 크기와 대비로 정보 계층을 구분한다.
- 화면은 `AppScreen`, 제목은 `AppHeroCard`, 일반 정보 묶음은 `AppSectionCard`를 사용한다. 일반 섹션은 구분선과 여백으로 나누며 장식용 그라데이션·그림자·중첩 카드를 추가하지 않는다.
- 버튼은 `AppPrimaryButton` / `AppSecondaryButton`, 입력창은 `AppTextField` / `AppOutlinedTextField`, 선택 필터는 `AppSelectableChip`으로 통일한다. 숫자 입력은 해당 키보드와 오류 상태를 제공한다.
- 기본 탐색은 홈·주식·카드·복권·전체의 5개 목적지다. 홈은 주식·카드·복권·화분·메모를 먼저 보여 주며, 기록·일기·통계·항목 관리는 생활 기록 영역과 전체 메뉴에서 접근한다.
- Structured처럼 핵심 흐름을 빠르게 훑을 수 있는 정보 계층을 사용하고, 기능별 톤 카드로 구분한다. 반투명 표면과 애니메이션은 헤더·진입 장면처럼 의미 있는 위치에만 제한적으로 사용한다.
- 작업 결과는 공통 Snackbar, 삭제·미저장 이탈·주문 전 확인은 명시적인 확인 대화상자를 사용한다.
- 일일 기록의 저장 버튼은 하단에 유지하고, 초안은 화면 재생성 시 복원한다. 달력 상태는 색 외에 기호와 접근성 설명을 함께 제공한다.
- 참고: [Android 모바일 레이아웃·탐색 가이드](https://developer.android.com/design/ui/mobile/guides/layout-and-content/layout-and-nav-patterns), [Material 3 in Compose](https://developer.android.com/develop/ui/compose/designsystems/material3), [Todoist 모바일 탐색](https://www.todoist.com/help/todoist/features/customize-the-todoist-navigation-bar-L4qpkI0xj). 2026년 9월 기준으로 확인했으며 신규 실험 API나 의존성 업그레이드 없이 적용한다.

배포 전에는 작은 화면·큰 글꼴·키보드 표시 상태, 일일 기록 작성 중 날짜 변경 및 화면 재생성, 카드 삭제 취소, 초기 DB 열기와 복원 경로를 기기에서 확인한다.
